# Cube layer

Model: `project/model/cubes/*.yml`, generated by `semglot build --profile cube`.

Run (Cube 1.6.76, Node 22, production mode):

```bash
uv run python scripts/make_duckdb_v14.py      # from the repo root, once
cd layers/cube/project
CUBESTORE_SKIP_POST_INSTALL=true npx -y node@22 "$(which npm)" install
NODE_ENV=production npx -y node@22 ./node_modules/@cubejs-backend/server/bin/server
# token: node -e "console.log(require('jsonwebtoken').sign({}, 'bench-local-secret'))"
```

Setup notes (environment only, no effect on the model):
- **Pinned to 1.6.76.** The 1.6.77 release has no darwin-arm64 native or Cube Store artifact.
- **Node 22.** Cube's native module does not load on Node 25.
- **Cube Store is skipped.** It is only needed for pre-aggregations, and none are defined.
- **Production mode.** Dev mode closes the shared DuckDB connection ("Database was already closed").
- **DuckDB v1.4 copy.** Cube's bundled DuckDB 1.4.4 cannot read the DuckDB 2.0 file, so
  `make_duckdb_v14.py` writes a v1.4-format copy, outside iCloud, with identical rows.
- `.env` (not committed) holds `CUBEJS_DB_TYPE=duckdb`, `CUBEJS_DB_DUCKDB_DATABASE_PATH` (the
  copy), `CUBEJS_API_SECRET=bench-local-secret`, `CUBEJS_SCHEMA_PATH=model`,
  `CUBEJS_CACHE_AND_QUEUE_DRIVER=memory` and `CUBEJS_DEV_MODE=false`.
