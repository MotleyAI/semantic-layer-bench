# Shared OSSIE model

`tpch.ossie.yaml` is the one baseline every layer gets. It is generated by `scripts/build_ossie.py`
from the vocabulary in `../model_contract.md`; edit the script, not the YAML. It is frozen once
step 3 (translation) starts, like the questions.

- Spec: Apache Ossie core spec `0.2.0.dev0`, expressions in `ANSI_SQL`.
- 10 datasets, 11 relationships (one composite: lineitem → partsupp), 11 metrics.
- Sources are `tpch.main.<table>` (DuckDB). Warehouse targets override the database/schema in
  their semglot profile (Snowflake: `SNOWFLAKE_SAMPLE_DATA.TPCH_SF1`).

## Validation (step 2)

| Check | Result |
|---|---|
| JSON Schema (`semglot/test/models/ossie/vendor/osi-schema.json`) | pass |
| semglot `ossie → ossie` round-trip | lossless: 11 metrics, 11 relationships, composite key kept |
| `slayer import-osi` (SLayer 1.7.0, DuckDB) | 10 models, 0 unconverted, 0 dropped |
| SLayer smoke queries: Q01 (total revenue), Q09 (4-hop region join) | match ground truth exactly |
